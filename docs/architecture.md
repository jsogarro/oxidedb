# OxideDB Architecture

OxideDB is currently a small q-inspired expression interpreter (the **O** language) with a REPL and file runner. Everything described outside the "Planned" section exists on `main`.

## Modules

### `src/language/`

- `lexer.rs`: turns a line of text into a `Vec<Token>` ending in `Token::Eof`. Handles integer and float literals, `1b`/`0b` booleans, `"c"` characters, `"abc"` strings (with `\" \\ \n \t \r` escapes), `` `a ``/`` `a`b `` symbols, `101b` boolean vectors, the comparison and punctuation tokens `= < > <> <= >= # , ! { } $ @ ' ': /: \: ::` (`= < > <> <= >= # , !` are verbs the parser accepts; the rest are reported as not yet implemented), identifiers (variable names; a literal glued to another, as in `1.5.5` or `"ab""cd"`, or a number glued to a letter, as in `2x` or `1E3`, is an invalid literal), the `0N`/`0n`/`0w` null and infinity literals, and `/` comments (a `/` at line start or after whitespace comments out the rest of the line).
- `parser.rs`: builds an `Expr` from the tokens. A run of juxtaposed number tokens becomes one literal: an atom for a single number, otherwise a long vector, or a float vector when any item is a float (a long null becomes `0n`). `Sym` is a symbol atom, `SymList` a symbol vector, `Str` a character vector, `BoolList` a boolean vector. The binary-chain parser accepts every verb token that maps to a `Verb` (`+ - * % = < > <> <= >= # , !`) with the same right-to-left rule and no precedence; a verb token where a noun is expected (`=1`, `#1 2`, `1 + ,2`) is `'nyi: <verb>`. A noun directly after a noun that is not part of such a run is application (`f x`, `v i`, `til 3+2`): it joins operands in the same flat chain as the verbs, so the left term applies to the whole expression on its right (`v 0 + 1` is `v (0 + 1)`, `count til 5` is `count (til 5)`). A `[` after a term starts an argument list (`f[a;b]`, `v[0 2][1]`, empty `[]`): brackets bind tighter than juxtaposition and chain, and `;` inside them separates arguments. An elided argument (`v[0;]`) is `'nyi: elided argument` and `name[i]:x` is an index assignment: the target must be a plain name with exactly one index (`v[0][1]:x`, `v[0;1]:x` and `1 2 3[0]:x` are `'nyi: depth assignment`; `v[]:x` assigns every item; a builtin applied, as in `count[0]:x` or `(neg v[0]):x`, is `'nyi: assignment to a function call`), the value takes the rest of the input like any assignment, and a verb after a name or an indexed name followed by a colon (`x+:1`, `v[0]+:1`) is `'nyi: compound assignment` (after anything else, `1+:2`, it is `'parse: unexpected :`). Every join (verb or application), every bracket suffix and every (sub)expression spends from the line's shared budget of 2,000 (see Evaluation pipeline); bracket contents nest like parentheses. Parentheses group (`(x)` is `x`), `()` is the empty general list, and two or more items separated by `;` are an `Expr::List`; each item is a full `expression()` and so spends from the budget, and an elided item (`(1;;2)`, `(1;)`) is `'nyi: elided list item`. Literal runs have no length cap (the token vector is already larger than the value).
- `ast.rs`: `Expr` (literal `Lit(Value)`, symbol (a variable name), binary op, unary op, `Apply { func, args }` for `f x` and `f[a;b]`, assignment, `List(items)` for `(a;b;c)`, `IndexAssignment { name, index, value }` for `name[i]:x`), the negate operator, and `Verb`, the binary verbs `+ - * % = < > <> <= >= # , !`. The parser produces all thirteen; `ops::dyad` evaluates them, and `!` (no kernel yet) gives `'nyi: !`.
- `interpreter.rs`: evaluates an `Expr` against a `HashMap<String, Value>` of variables. `Interpreter::eval_line` runs the whole pipeline for one line. Verbs are applied by `ops`. `Apply` evaluates its arguments right to left, then the function. `List` evaluates its items right to left, builds the value with `Value::from_items` and checks it with `check_nesting`. A name is looked up in the variables first and then in the builtins; a bare builtin name is `'nyi: <name> as a value` (there are no function values yet) and assigning to a builtin name is `'parse: cannot assign to builtin <name>` (refused while parsing). `IndexAssignment` evaluates the value first and then the index (right to left, as q does), then reads the name: an undefined name is `'<name> (Undefined variable)`, the error a read gives (a deliberate deviation: q reads an undefined name as an empty list and answers `'length`), and the expression's value is `apply` of the amended target to the index, so a repeated index shows what the vector holds afterwards.
- `apply.rs`: applying a value to arguments. An atom cannot be applied (`'type`; q reads an integer atom applied to an argument as a file handle, which O does not imitate). A vector or general list takes one index: an atom index (long or boolean) gives an item, a vector or list of indexes gives a vector or list of items, via `Column::index`; negative and out-of-range positions give the typed null (a general list gives the null of its first item, as q does: an atom's null, an empty vector of a vector's type, a list of nulls for a list, `()` for `()`); a float, symbol or character index is `'type`; no arguments gives the value back; several arguments are `'rank` for a vector and `'nyi: depth indexing` for a list. `amend` is the setter behind `v[i]:x`, in q's order of checks: an atom target is `'type`; the index must be long or boolean (`'type`); every position must satisfy `0 <= p < len` (`'length`, where a read gives a null; q has no `'index`); a vector index takes an atom (broadcast) or exactly one value per position (`'length`), an atom index takes an atom only (`'type`); a vector target then needs the value's exact column type (`'type`, no promotion, via `Column::assign`). A general list also rejects new items nested deeper than `MAX_VALUE_DEPTH` (64) with `'limit: nesting deeper than 64` and a list whose logical size (items counted once per path, so a sub-list shared twice counts twice; `Value::logical_size`, memoised per `Rc`) would exceed `MAX_LOGICAL_ITEMS` (1,000,000) with `'limit: value larger than 1000000 items`. Both are enforced by `Value::check_nesting`, which every operation that creates nesting must call: equality, arithmetic, negation, display and drop recurse per level, every walk visits every path, and neither the per-line budget nor the depth cap can see a list that sharing doubles each round (`l[0]:l; l[1]:l`). `amend` computes the exact size after the change only when something larger than an atom goes in, crediting the replaced items; the results of `ops::dyad` and `ops::monad_neg` that are lists are checked too (join and take can multiply a value that is within the caps). A general list of long and boolean atoms is accepted as an index, like a vector. All checks run before anything changes, and the change goes through `Rc::make_mut`, so another name sharing the vector keeps the old contents. A general list takes any value, and after the change it collapses to a vector if every item is now an atom of one type (`Value::from_items`), as in q. A repeated position takes the last value. A character index (even an empty one, `v[0#"a"]:9`) is `'type` (q reads it as its code point). The collapse test stops at the first item that is not an atom of the first item's type, so a list that cannot collapse is usually left alone without a scan.
- `builtins.rs`: `lookup(name)` resolves a keyword to a `Builtin` (`name`, `arity`, `call`); `call(name, args)` wraps it. Keywords: `til`, `count`, `neg` (`ops::monad_neg`, the same kernel as the leading minus) and `enlist` (`Value::from_items` of the one argument, nesting-checked: an atom gives a one-item vector, anything else a one-item general list; q's variadic `enlist[a;b]` is a `'rank` error here). `til` and `Column::take` share the `MAX_ELEMS` cap (10,000,000 elements, `'domain` beyond it). A builtin takes exactly one argument (`'rank` otherwise, including `til[]`, where q passes a null); `til` accepts only a long (q also accepts a boolean).
- `ops/`: verb kernels over `Value`s. `ops::dyad(verb, &l, &r)` and `ops::monad_neg(&v)` are the entry points. `ops/arith.rs` implements `+ - * %` atomically: atoms, vectors (broadcast, or pairwise with equal lengths) and general lists (item-wise, renormalised through `Value::from_items`). A boolean counts as a long, long with float is float, `%` is always float, a long null stays null (`0n` once a float is involved), and any element overflowing is `'overflow`. Symbols, characters and temporals are `'type`; a length mismatch is `'length`. `ops/compare.rs` implements `= <> < <= > >=` with the same broadcasting and length rules, returning booleans (a `Bool` column for vectors): bool, long and float compare by value, null equals null and sorts lowest, symbols compare by name, characters by code, and mixing kinds (symbol or character with a number, or with each other) is `'type`. Deliberate deviations from q: comparing a character with a number is `'type` (q compares by code), and float `=` is exact (q is tolerant); a long against a float compares after conversion to float, as in q, so above 2^53 distinct longs can equal a float. `ops::atomic` is the shared list recursion. `ops/take.rs` implements `n#x`: the count must be a long atom (a boolean counts as 0 or 1; a float, character, symbol or `0N` count is `'type`, a list of counts would reshape and is `'nyi: reshape`, and a count over `MAX_ELEMS` is `'domain`); it takes cyclically from the front, or from the end for a negative count; an atom repeats; an empty vector gives typed nulls and `()` gives `()` items; a general list result is renormalised through `Value::from_items`; temporal atoms (no column type) repeat as a general list. `ops/join.rs` implements `x,y`: two atoms or vectors of one type give a vector, anything else a general list of all the items (no promotion, so `1,2.5` is `(1;2.5)`), renormalised through `from_items` (`(1;2),3` is a long vector); an empty operand, typed or `()`, is an identity whatever its type (`(0#0),1.5` is `,1.5`); a result over `MAX_ELEMS` is `'domain`. Verbs without a kernel (`!`) give `'nyi: <verb>`. Lengths are checked before element types, so `1 2 3+`a`b` is `'length` as in q, except that q reports `'type` for `x - symbols` (O is uniform: `1 2 3-`a`b` is `'length`). Further deliberate deviations: a null-symbol count (`` `#x ``, which q treats as clearing attributes) is `'type`; a list count is `'nyi: reshape` although q takes for a one-item long list (`(enlist 2)#1 2 3` is `1 2`) and returns `x` for `(0#0)#x`; the `MAX_ELEMS` cap on results (q 4.1 returns `10000001#1`). Deliberate deviation: arithmetic on characters is `'type` (q computes with character codes: `"abc"+1.5` is `98.5 99.5 100.5`).

### `src/types/`

- `atom.rs`: the scalar `Atom` enum (boolean, long, float, character, symbol, date, time, timestamp, and typed temporal nulls) with q type codes and q-style display.
- `sym.rs`: interned symbols, a 4-byte handle into a process-global string table. Interned names are never freed.
- `column.rs`: `Column`, a typed vector (bool, long, float, char, symbol). Vector literals build one (`Value::Vector`). `index` (typed gather, typed nulls for bad indices), `assign` (typed scatter behind item assignment; `'type` on a different column type), `take` (q `#`, cyclic, negative from the end) and `concat` (same type only) are the helpers indexing, take and join build on.
- `value.rs`: `Value`, the result of evaluation (atom, vector or general list), its equality and display.
- `display.rs`: q-style `Display` for `Column` (`1 2 3`, `1 2 3f`, `101b`, `` `a`b ``, `"abc"`) and the character escaping shared with `Atom`'s `Display`. It also renders a general list the way the q console does (`lines`, taken from q's own `.Q.s` definition): one line per item, an atom item as itself, a nested general list in its `(a;b)` form (`,x` for one item, `()` for none); but when no item is an atom and all have the same length (and they are not all boolean or all character vectors) the items are rows of a table: each row is cut into cells (a vector's elements with no type marks, a null blank; a nested list by the same rule), every column is padded to its widest cell and the cells are joined with one space. `()` itself prints as the empty string, and `Repl::eval_line` prints no line at all for it. Not reproduced: q cuts a long line or a tall list short with `..`; O prints everything, as it does for vectors. Display is recursive and walks every path of a shared list, so it is bounded by `check_nesting` (depth 64, 1,000,000 logical items); an item in its own form is streamed, and only a matrix is built as one string first.

### `src/repl/` and `src/main.rs`

`Repl` wraps a `rustyline` editor and one `Interpreter`. `main` starts the interactive loop, or runs a file when given a path argument.

## Evaluation pipeline

1. **Tokenize**: `Lexer::tokenize`. A line with no tokens other than `Eof` (blank or comment-only) evaluates to nothing.
2. **Parse**: `Parser::parse`. A flat operator chain is parsed iteratively into a right-nested tree, so there is no precedence: `1+2*3` is `1+(2*3)`. Limits keep recursion bounded: nesting of parentheses, brackets and monadic minus is capped at 128, and one budget of 2,000 is shared by the whole line (every expression, including each nesting level, unary minus and assignment value, every operator join, every juxtaposition and every bracket suffix spends one), so a flat chain holds at most 1,999 operators and the right-nested tree is never deeper than 2,000 levels however chains and nesting are combined. Exceeding either limit is an error (`'parse: expression nested too deeply` / `expression too long`), not a crash. The binary also runs the whole session on a thread with a 64 MB stack (`src/main.rs`); the worst case at the budget is an application chain (`count count ... 1`), which needs about 4.5 MB in a debug build and 1.4 MB in release (an operator chain needs 2.9 MB and 0.7 MB; nested shapes are lower), so a library caller on a default 8 MB thread is safe in both with margin. Library callers should evaluate lines on a thread with at least 6 MB of stack in debug builds (a 2 MiB thread aborts at the budget in a debug build); the binary uses a dedicated 64 MB thread. Assignment nesting is capped by the nesting limit as well.
3. **Evaluate**: `Interpreter::evaluate`. The right operand is evaluated before the left, as in q, including side effects such as assignment. Mixed long/float arithmetic promotes to float; `%` is always float division.

## Values

Evaluation returns a `Value` (`src/types/value.rs`): an `Atom`, a `Vector(Rc<Column>)` (typed, one element type) or a `List(Rc<Vec<Value>>)` (general list, type code 0). Atoms have negative type codes, vectors positive, general lists 0. `Value::from_items` is the one constructor for lists: items that are all atoms of one column type become a `Vector` (no int to float promotion); empty input or anything else is a `List`. Variables hold `Value`s, so reading a vector variable is a reference-count bump. `Interpreter::set` and `get` bind and read variables from the library API.

Equality treats nulls as equal (`0n` equals `0n`, in atoms, columns and lists), while `0f` and `-0f` stay equal. `Value` also compares with `Atom` in both directions, so an atom result can be asserted directly. A general list prints one item per line (see `display.rs`); `()` prints nothing. Nesting is capped at runtime too: list literals and `enlist` pass their result through `Value::check_nesting` (depth 64, 1,000,000 logical items, `'limit` beyond), so a script cannot grow a value one level, or one doubling, per line.

Literals are `Expr::Lit(Value)`, so evaluating one is a reference-count bump. Arithmetic is atomic: `+ - * %` and unary minus extend over atoms, vectors and lists (see `ops/arith.rs` above), so `1 2 3 + 1` and `- 1 2 3` evaluate. The parser produces every `Verb`: `= < > <> <= >=` evaluate through `ops/compare.rs` (`1 2 3 = 1 5 3` is `101b`); `#` and `,` evaluate through `ops/take.rs` and `ops/join.rs`, and `!` gives `'nyi: !`.

Symbols have literals (`` `a `` is an atom, `` `a`b `` a vector); date, time and timestamp atoms exist as types, but the language has no literal for them yet. Long, float, character and symbol nulls are sentinels, not separate variants: `Integer(i64::MIN)`, `Float(NaN)`, `Character(' ')`, `Symbol(Sym::NULL)`. Producing `i64::MIN` by arithmetic is reported as overflow. Only the temporal nulls have their own variants. Variables live in the interpreter's map for the length of the session and are not saved.

## Error handling

Lexing, parsing and evaluation return `Result<_, QError>` (`src/error.rs`). `QError` is a q-style error whose text is a quote and a short name: `'type`, `'overflow`, `'parse: <detail>`, `'<name> (Undefined variable)`, `'nyi: <detail>`; `length` is raised by arithmetic on vectors of different lengths; `rank` is raised by a wrong number of arguments or indexes; `stack` and `signal` are defined for later features; `limit: <detail>` is raised when a value would nest deeper than `MAX_VALUE_DEPTH` or hold more than `MAX_LOGICAL_ITEMS` items counting shared lists per path; `domain` is raised by `til` of a negative number and by the size limit of `til`, take and join (`builtins.rs`, `column.rs`, `ops/join.rs`). Malformed input and the limits above are `Parse`, features O does not have yet (`0W`, adverbs, lambdas, `$` and `@`, elided arguments) are `Nyi`, unsupported operand types are `Type`, and integer overflow is `Overflow`. A lexer error names the offending literal (`'parse: invalid literal: 2x...` for a number glued to a letter); the parser names an unexpected token in source form (`1 )` gives `'parse: unexpected ) after expression`). The REPL prints the error text on stderr and keeps the session; `run_file` stops at the first failing line and prints the error once with its line number (`line 3: 'type`); the `QError` stays the source of the returned `anyhow` error, and the process exits with status 1.

## Testing

- `tests/*.rs`: one integration test file per area (arithmetic, atoms, comments, display, literals, nesting limits, parsing, types, file running). They drive the public API (`Interpreter`, `Lexer`, `Parser`).
- `tests/robustness.rs`: property tests (`proptest`) asserting that arbitrary input never panics.
- `tests/book_examples.rs`: runs every expected output in `book/` and `book/examples/` through the real interpreter.
- `benches/performance.rs`: Criterion benchmarks for the lexer, parser, evaluator and the full line pipeline.

There are no `#[cfg(test)]` modules in `src/`.
